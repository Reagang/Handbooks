# CC1001: Unnecessary LINQ materialization

| Property | Value       |
|----------|-------------|
| Category | Performance |
| Severity | Warning     |

## Cause

A LINQ chain calls `ToList()` or `ToArray()` and then immediately chains
another LINQ operator on the result.

## Rule description

`orders.Where(x => x.Active).ToList().FirstOrDefault()` allocates a full
list just to throw it away one call later. Composing the operators over the
original `IEnumerable<T>` avoids the intermediate allocation and lets the
later operator (e.g. `FirstOrDefault`) short-circuit instead of forcing
full enumeration.

## How to fix violations

Drop the `ToList()`/`ToArray()` and move its filter/projection into the
following call, or push it directly onto the source sequence.

## Example

```csharp
// Violation
orders.Where(x => x.Active).ToList().FirstOrDefault();
```

```csharp
// Fixed
orders.FirstOrDefault(x => x.Active);
```

## When to suppress

Suppress when the intermediate list is genuinely needed for something else
in scope (e.g. it's returned, stored, or enumerated more than once) rather
than only feeding the very next call.
