# CC1003: Magic constant in comparison

| Property | Value           |
|----------|-----------------|
| Category | Maintainability |
| Severity | Warning         |

## Cause

A hardcoded numeric or string literal (other than `0`, `1`, `-1`, or `""`)
appears in an equality/relational comparison or a `switch` case label.

## Rule description

`if (status == 5)` doesn't tell the reader what `5` means, and the same
magic value tends to get retyped - inconsistently - wherever the check is
needed again. A named constant, enum member, or strongly typed option
documents the intent once and keeps every call site in sync.

`0`, `1`, `-1`, and `""` are allowed: they usually read as self-explanatory
sentinels (empty, none, not-found, increment) rather than business values.

## How to fix violations

- Use a named `const`.
- Use an `enum` when the value is one of a closed set of states.
- Use a strongly typed options object for configuration-shaped values.

## Example

```csharp
// Violation
if (status == 5) { }
```

```csharp
// Fixed
if (status == OrderStatus.Completed) { }
```

## When to suppress

Suppress in generated code, test fixtures asserting against literal
expected values, or one-off scripts where introducing a named constant
would add indirection without adding clarity.
