# DI1002: Duplicate service registration

| Property | Value               |
|----------|---------------------|
| Category | DependencyInjection |
| Severity | Warning             |

## Cause

The same service type is passed to `AddSingleton<TService, _>`,
`AddScoped<TService, _>`, or `AddTransient<TService, _>` more than once
within the same method.

## Rule description

The last registration wins for a non-collection service, so a second
registration for the same `TService` silently overrides the first one
(possibly registering the wrong implementation, or the wrong lifetime)
rather than raising an error. That makes container configuration
order-dependent and hard to audit.

`TryAddSingleton`/`TryAddScoped`/`TryAddTransient` are exempt: calling
those a second time for the same service is the documented,
"register-if-absent" way to make a default overridable.

## How to fix violations

- Centralize the registration in one place.
- If the intent really is "register only if nothing else already did",
  use the `TryAdd*` family instead.

## Example

```csharp
// Violation
services.AddSingleton<IMyService, MyService>();
// ... elsewhere in the same method ...
services.AddSingleton<IMyService, MyService>();
```

```csharp
// Fixed
services.AddSingleton<IMyService, MyService>();
```

## When to suppress

Suppress if a later registration is a deliberate override for a specific
environment/feature flag branch within the same method - though moving
that branch into its own extension method usually reads better.
