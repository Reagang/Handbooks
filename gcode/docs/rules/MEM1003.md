# MEM1003: Finalizer without GC.SuppressFinalize

| Property | Value  |
|----------|--------|
| Category | Memory |
| Severity | Warning |

## Cause

A class declares a finalizer (`~ClassName()`) but no method in the class
calls `GC.SuppressFinalize(this)`.

## Rule description

An object with a pending finalizer survives at least one extra GC
generation: the collector defers reclaiming it until the finalizer has run
on a dedicated finalizer thread. When the object is disposed
deterministically (`Dispose()` already released the unmanaged resource),
calling `GC.SuppressFinalize(this)` tells the GC the finalizer is no longer
needed, so the object can be collected on its regular generation instead.
This is the standard second half of the dispose pattern whenever a
finalizer is present.

## How to fix violations

Call `GC.SuppressFinalize(this)` at the end of `Dispose()`.

## Example

```csharp
// Violation
~Resource()
{
    ReleaseUnmanaged();
}

public void Dispose()
{
    ReleaseUnmanaged();
}
```

```csharp
// Fixed
~Resource()
{
    ReleaseUnmanaged();
}

public void Dispose()
{
    ReleaseUnmanaged();
    GC.SuppressFinalize(this);
}
```

## When to suppress

There's rarely a reason to suppress this one - a finalizer with no
`GC.SuppressFinalize` anywhere in the type is almost always a bug. If the
type intentionally always needs finalization even after `Dispose()`
(unusual), remove the finalizer instead of suppressing the warning.
