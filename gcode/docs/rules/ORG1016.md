# ORG1016: String concatenation in a loop

| Property | Value       |
|----------|-------------|
| Category | Performance |
| Severity | Info        |

## Cause

A `string`-typed variable is built with `+=` inside a `for`, `foreach`,
`while`, or `do` loop.

## Rule description

`string` is immutable, so `result += item` allocates a brand-new string
and copies the old contents into it on every iteration. Over N iterations
that's O(N) allocations and O(N²) copied characters. `StringBuilder`
amortizes this to O(N) by growing its internal buffer instead of
reallocating a full string each time.

This only looks at the loop directly enclosing the `+=`; concatenation
inside a lambda or local function isn't flagged even if that lambda is
invoked from within a loop, since whether it actually runs once per
iteration isn't decidable from syntax alone.

## How to fix violations

Use a `StringBuilder`, and call `ToString()` once after the loop.

## Example

```csharp
// Violation
var result = "";
foreach (var item in items)
{
    result += item;
}
```

```csharp
// Fixed
var builder = new StringBuilder();
foreach (var item in items)
{
    builder.Append(item);
}
var result = builder.ToString();
```

## When to suppress

Suppress for loops with a small, fixed, known-tiny iteration count where
the allocation is immaterial and a `StringBuilder` would just add noise.
